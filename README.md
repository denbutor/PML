# E-Commerce Customer Retention & Dynamic Pipeline Engine (ЛР1)

Системний дизайн ML-системи за методологією **CRISP-ML(Q)** та стандартом **REFORMS** для прогнозування відтоку клієнтів в E-commerce.

## 1. Machine Learning Canvas

| Блок Canvas | Зміст |
|---|---|
| **Business Goal** | Раннє виявлення клієнтів з високим ризиком відтоку для своєчасного вжиття маркетингових заходів (знижки, спецпропозиції), уникаючи перевитрат на лояльну аудиторію. |
| **Value Proposition** | Автоматичне формування ранжованого за ризиком списку клієнтів для CRM-менеджерів замість суцільних розсилок. |
| **Non-ML Benchmark** | Просте правило: `Tenure <= 1` **АБО** `Complain == 1` -> **Accuracy = 0.699**, **Recall = 0.848**, **Precision = 0.341**. |
| **ML Metric** | **Recall >= 0.80** при **Precision >= 0.50** на тестовому зрізі; ROC-AUC >= 0.85. |
| **Data Sources** | E-Commerce Dataset (Kaggle, Ankit Verma): 5 630 спостережень, 20 атрибутів. |
| **Constraints** | Ізоляція захищених атрибутів (`CityTier`, `Gender`); час обробки < 1 с/клієнт; повна детермінованість. |
| **Cost of False Alarms** | FP — марна знижка та звикання до промокодів; FN — втрата клієнта та його LTV (FN набагато критичніше за FP). |
| **Deployment Context** | Щомісячний пакетний (batch) скоринг бази клієнтів з інтеграцією в CRM. |
| **Feedback Loop** | Фіксація фактів відтоку через 30 днів; логування фактів маркетингових втручань для запобігання зсуву розподілу (data drift). |

## 2. Етичний комплаєнс та проксі-ознаки

* **Захищені атрибути:** `CityTier` (географічна кагорта/рівень доходу) та `Gender` (стать).
* **Причина виключення:** Запобігання прямої дискримінації клієнтів з регіональних міст (Tier 3 має базовий відтік 21.4% проти 14.5% у Tier 1).
* **Проксі-аналіз:** Ознаку `PreferredPaymentMode` ідентифіковано як потенційний проксі (`E wallet` переважає у Tier 3, Cramér's V = 0.44). Ознака залишена для прогнозування, але підлягає аудиту справедливості (Fairness Audit) у наступних роботах.

---

## 3. Схема класифікації `model_family`

Обрано схему **`scale_sensitive` / `scale_invariant`**:
* **`scale_sensitive`**: Моделі, чутливі до масштабу та форми розподілу значень (Логістична регресія, SVM, Нейромережі). Потребують `log1p`, `StandardScaler` та `WoE`.
* **`scale_invariant`**: Деревоподібні моделі (Random Forest, XGBoost), що спираються на порогові предикати. Не потребують шкалювання; вимагають вінсоризації для ізоляції поодиноких викидів.
